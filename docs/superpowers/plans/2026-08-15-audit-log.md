# Connection Audit Log Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a real, wired-up Audit Log to each PostHog connection — every meaningful thing that happens to it (established, settings changed, resynced, a pipeline sync completed or failed) leaves a real timestamped entry, visible in a new collapsible "AUDIT LOG" section on the connection's settings card.

**Architecture:** New `connection_events` D1 table, one small `logConnectionEvent` helper, five write points wired into routes that already exist (plus one new pipeline-authed failure-report route), one new session-authed read route, and a frontend collapsible section reusing the existing `.conn-group` pattern, lazy-loaded on first expand. `bug_radar.py` gets a top-level try/except so an unhandled exception is reported instead of silently killing the process with nothing recorded.

**Tech Stack:** Cloudflare Workers + D1 (`worker/src/index.js`), vanilla-JS frontend with manual `render()`/`data-act` dispatch (`worker/public/index.html`), Python pipeline (`bug_radar.py`).

**Spec:** `docs/superpowers/specs/2026-08-15-audit-log-design.md`

## Global Constraints

- No unit test framework anywhere in this codebase — verification is real calls: curl, `wrangler d1 execute --remote --command "..." ` (needs `CLOUDFLARE_ACCOUNT_ID=ad1a4dda1125569690132b861f95a63a` set in the environment when more than one Cloudflare account is available, or `wrangler` will refuse to run non-interactively), and a Playwright pass. Every task's Verify step follows this.
- D1 database name: `bug-radar-db`. Deployed Worker URL: `https://bug-radar.shubhamvishnu.workers.dev`.
- Pipeline service secret: macOS Keychain `BUGRADAR_API_SECRET`, retrieved via `security find-generic-password -s "BUGRADAR_API_SECRET" -w` into a shell variable — never echo the value itself.
- This project works directly on `main`, no feature branches — commit each task directly, and push to `origin/main` after each commit (standing project convention).
- Deploy after each task that touches `worker/` (`cd worker && npx wrangler deploy`) so verification curls hit real, current behavior.
- `connection_events.status` values map directly to dot colors in the UI: `success` (green), `warning` (amber), `error` (red), `info` (slate). Use exactly these four strings, nothing else.

- [ ] **Step 2: Change `resolveTags`'s return shape and track only genuinely-new inserts**

Search for `async function resolveTags(env, ownerEmail, findings) {`. Read its current full body (it's about 35 lines) and replace the whole function with:

```javascript
async function resolveTags(env, ownerEmail, findings) {
  const createdThisBatch = new Map(); // normalized label -> tag id
  let newlyCreatedCount = 0;
  const countRow = await env.DB.prepare("SELECT COUNT(*) as n FROM tags WHERE owner_email = ?").bind(ownerEmail).first();
  let nextColorIndex = countRow.n;
  for (const f of findings) {
    for (const t of f.tasks || []) {
      if (!Array.isArray(t.tags)) continue;
      for (const tg of t.tags) {
        if (!tg || typeof tg !== "object") continue;
        if (!tg.tag_id && tg.new_tag && tg.new_tag.label) {
          const key = tg.new_tag.label.trim().toLowerCase();
          let tagId = createdThisBatch.get(key);
          if (!tagId) {
            const existing = await env.DB.prepare(
              "SELECT id FROM tags WHERE owner_email = ? AND lower(label) = ?"
            ).bind(ownerEmail, key).first();
            if (existing) {
              tagId = existing.id;
            } else {
              const color = TAG_PALETTE[nextColorIndex % TAG_PALETTE.length];
              nextColorIndex++;
              const result = await env.DB.prepare(
                `INSERT INTO tags (owner_email, label, color, source) VALUES (?, ?, ?, 'auto')`
              ).bind(ownerEmail, tg.new_tag.label.trim(), color).run();
              tagId = result.meta.last_row_id;
              newlyCreatedCount++;
            }
            createdThisBatch.set(key, tagId);
          }
          tg.tag_id = tagId;
        }
        tg.assign = "auto";
        delete tg.new_tag;
      }
    }
  }
  return { findings, count: newlyCreatedCount };
}
```

This is byte-for-byte the same logic as before, with two additions: a `newlyCreatedCount` variable incremented only in the true-INSERT branch (not when an existing tag is reused, whether from this batch or the DB lookup), and the return shape change.

function relTimeLabel(iso) {
  const ts = iso.includes("T") ? iso : iso.replace(" ", "T") + "Z";
  const mins = Math.max(0, Math.round((Date.now() - new Date(ts).getTime()) / 60000));
  if (mins < 1) return "just now";
  if (mins < 60) return `${mins}m ago`;
  const hrs = Math.round(mins / 60);
  if (hrs < 24) return `${hrs}h ago`;
  return `${Math.round(hrs / 24)}d ago`;
}

async function loadConnEvents(id) {
  const res = await fetch(`/api/connections/${id}/events?limit=20`);
  if (res.ok) state.connEventsCache[id] = await res.json();
  render();
}

function toggleAuditLog(id) {
  const wasOpen = !!state.connEventsOpen[id];
  state.connEventsOpen[id] = !wasOpen;

    loadConnEvents(id);
